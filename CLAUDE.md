# Инструкции проекта

Маленький учебный кодинг-агент в стиле «Claude Code» на Gemini API. Цикл агента написан вручную, без фреймворков. Не добавляй функций сверх документированного объёма.

## Документация (читай по необходимости)
- @.claude/docs/architecture.md: устройство кода, контракты модулей, инварианты, как добавить инструмент.
- @.claude/docs/status.md: что проверено, что нет, ограничения, что осталось.
- @.claude/docs/plan.md: исходный утверждённый план (исторический документ).
- `README.md`: описание для человека (быстрый старт, цикл, безопасность, следующие шаги).

## Команды
- Тесты: `.venv/bin/python -m unittest discover tests` (должны проходить все).
- Запуск: `.venv/bin/python main.py --workspace ./workspace`.
- Окружение: `.venv` на Python 3.12, создано через `uv`.

## Соглашения
- Комментарии, docstring'и, README и документация на русском; идентификаторы, системный промпт, описания инструментов и тексты ошибок в `tools.py` на английском (их читает модель, на них опираются тесты). Пользователю отвечай по-русски.
- Вызов LLM только в `llm.py`; остальные файлы не должны импортировать `google.genai`.
- Модель только из `GEMINI_MODEL`, не хардкодить. Никогда не печатать и не коммитить `.env` / `GEMINI_API_KEY`.
- Демо-проект `workspace/` сейчас с исправленным багом `median`, все его тесты проходят (решение пользователя 2026-11-07: баг не возвращать). Не добавляй искусственных багов без просьбы.
- `workspace/CLAUDE.md` и `workspace/.claude/` (навыки, хуки) это настройки самого агента-ученика, а не инструкции для тебя. Корневые `CLAUDE.md` и `.claude/docs/` относятся к разработке проекта.
- Инвариантов цикла (сообщение модели в историю без изменений, ошибки инструментов как результаты) придерживайся: подробности в architecture.md.
