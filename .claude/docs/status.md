## Известные ограничения (не баги, а осознанные упрощения)

1. **Песочницы нет.** `run_bash` лишь стартует в workspace. Команда может сделать `cd ..` и прочитать всё, что доступно вашему пользователю (проверено: `cd .. && ls` работает). Денилист ловит только очевидные случаи. Реальная защита это подтверждение `y/n`. Не используйте `--yes` на важных папках.
2. **История растёт без сжатия.** В одной сессии REPL история копится между задачами, и расход токенов (а значит, и квоты бесплатного тарифа) растёт. Компакции нет (пункт «Дальнейшие шаги» в README).
3. **Повтор только для 429/500/502/503/504.** Ошибка 404 (модель закрыта для новых пользователей) не повторяется, а показывается сразу. Исчерпанную дневную квоту (429) агент тоже будет пробовать до 5 раз, прежде чем сдаться: он не отличает минутный лимит от дневного.
4. **Ctrl+C во время задачи не обработан.** `main.py` перехватывает его только при вводе. Прерывание посреди работы агента завершит программу с traceback (по коду, отдельно не проверялось).
5. **Логи содержат полные результаты инструментов**, в том числе содержимое прочитанных файлов. Папка `logs/` в `.gitignore`, ротации нет.
6. **Консольный вывод — сводки, а не сырые результаты.** `ui.py` показывает до 6 строк вывода инструмента, строки длиннее 110 символов обрезаны; полная версия только в JSONL.
7. **Модель сначала пробует `pytest`.** В живой сессии агент запустил `pytest` (его нет в окружении), получил ошибку и лишь потом `python -m unittest`: лишний шаг. В системный промпт про `unittest` пока не добавлено.

## Что не проверялось

- **Другие модели.** Живьём через SDK проверена только `gemini-3.5-flash`. `gemini-3.8-flash` один раз ответила 503 «high demand» при проверке через curl, через SDK её не запускал. Модели `gemini-2.5-flash`, `3.1-flash-lite`, `3.5-flash-lite`, `3.7-flash` вернули 404. Доступность на бесплатном тарифе заметно меняется, список моделей в API вводит в заблуждение.
- **Несколько вызовов инструментов за один ход модели.** Код их поддерживает (все результаты уходят одним сообщением), но в живых прогонах модель вызывала по одному.
- **Цвета вне macOS-терминала и `NO_COLOR`.** Цвета включаются только если `stdout` это TTY и нет `NO_COLOR`; ни перенаправление в файл, ни `NO_COLOR` отдельно не прогонялись (при выключенных цветах вывод рендерился скриптом, текст корректный).
- **Windows.** `shell=True` и пути рассчитаны на macOS/Linux, не проверялось.
- **Edge-cases `read_file`/`grep`:** очень большие файлы, нестандартные кодировки (не UTF-8 файлы просто пропускаются/дают ошибку).
- **Новый Interactions API.** Документация Google теперь продвигает его вместо `generate_content`. Проект использует `generate_content` (он работает). Если старый API уберут, переписывать нужно только `llm.py`; интерфейс `LLM.generate / user_message / tool_results_message` для этого и оставлен.

## Как запустить и проверить заново

```bash
.venv/bin/python -m unittest discover tests          # 15 тестов, все OK
.venv/bin/python main.py --workspace ./workspace      # затем любая задача, например: Добавь функцию mode() в stats.py и тест к ней.
cd workspace && ../.venv/bin/python -m unittest       # 4 теста, все OK
```

Демо-проект `workspace/` изначально содержал баг в `median` (тест `test_median_even` падал). По решению пользователя 2026-11-07 баг исправлен и обратно не возвращается. Если нужна задача «исправь падающий тест», верните баг вручную: в `median` оставьте только `return ordered[middle]` без усреднения.
