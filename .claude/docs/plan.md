# План: маленький кодинг-агент в стиле «Claude Code» на Gemini (цикл написан вручную)

## Контекст
Учебный проект в `/Users/islambek_sadykov/Desktop/idk`: Python-агент на ~300–500 строк, который читает/ищет/правит файлы и запускает shell-команды внутри рабочей папки, с вручную написанным циклом агента (без фреймворков). Требования взяты из вставленной спецификации; никаких функций сверх неё.

## Что я проверил в Gemini API (до планирования)
- `.env` уже существует с `GEMINI_API_KEY` (я его никогда не печатал). Ключ рабочий: `GET /v1beta/models` отвечает.
- **Список моделей вводит в заблуждение.** `gemini-2.5-flash` есть в списке, но `generateContent` возвращает 404 «no longer available to new users». Несколько других моделей из списка (3.1-flash-lite, 3.5-flash-lite, 3.7-flash) тоже дали 404.
- **`gemini-3.5-flash` один раз сработала** с вызовом функций: вернула `functionCall` (с `id`) и `thoughtSignature`.
  Последующие вызовы той же модели и `gemini-3.8-flash` вернули 404 (3.8-flash один раз также вернула 503 «high demand»). Поведение выглядит нестабильным, поэтому первым шагом реализации идёт настоящий smoke-тест через SDK.
- Страницы документации переехали на aistudio.google.com и теперь продвигают новый **Interactions API**. Загруженная страница описывала только этот API, но не `generate_content`, поэтому синтаксис `generate_content` + `automatic_function_calling` по документации не подтверждён. Smoke-тест (шаг 1) подтверждает его на установленном SDK. Поскольку вызов LLM живёт только в `llm.py`, переход на другой стиль API потом — правка одного файла.
- Локальный Python — 3.9.6; новейший `google-genai` для 3.9 — 1.47. `uv` установлен, поэтому я создам venv с Python 3.12 и актуальным SDK.

## Проектные решения
- **Модель**: переменная окружения `GEMINI_MODEL`, по умолчанию `gemini-3.5-flash` (единственная проверенная на данный момент; скорректирую после smoke-теста). Альтернативы для проверки: `gemini-3.8-flash`, `gemini-flash-latest`.
- **Ручной цикл**: `automatic_function_calling=AutomaticFunctionCallingConfig(disable=True)`; читать `response.function_calls`; запускать инструменты; добавлять результаты; повторять до текстового ответа или максимума шагов (25).
- **Thought signatures**: добавлять `candidates[0].content` модели в историю *без изменений* (никогда не пересобирать из текста), иначе Gemini 3 может отклонить или ухудшить следующий ход. Я объясню это в комментарии.
- **Заменяемый провайдер**: `llm.py` предоставляет небольшой нейтральный интерфейс: `LLM.generate(history, system, tool_schemas) -> Reply(text, tool_calls, usage, message)`, плюс `user_message(text)` и `tool_results_message(results)`. `agent.py` считает сообщения истории непрозрачными, поэтому переход на Claude потребует переписать только `llm.py`.
- **Повторы**: экспоненциальный backoff + jitter при 429/500/503/таймаутах, максимум ~5 попыток, с выводом пользователю.
- **Тесты/зависимости**: только стандартный `unittest` (без pytest), чтобы демо-проект и модульные тесты не требовали ничего лишнего. Единственные зависимости: `google-genai`, `python-dotenv`.

### Поведение инструментов
- `safe_path`: `Path(workspace, p).resolve()`, затем `relative_to(workspace.resolve())`; `resolve()` следует по симлинкам, поэтому выходы через симлинки тоже отклоняются.
- `read_file(path, offset, limit)`: построчно, возвращает пронумерованные строки. `write_file`: создаёт родительские каталоги, полная перезапись. `edit_file`: `count(old_text)` должно быть ровно 1.
- `glob(pattern)`: `Path.glob` внутри рабочей папки, пропускает `.git`/`.venv`, с ограничением. `grep(pattern, path)`: Python `re` по файлам, возвращает `file:line:text`, с ограничением, пропускает бинарные файлы.
- `run_bash`: `subprocess.run(shell=True, cwd=workspace, timeout)`; возвращает stdout+stderr+код выхода. Denylist (`rm -rf /`, `sudo`, `mkfs`, форк-бомба, `curl|sh`...). Примечание: ограничение cwd — это не песочница (команда всё равно может сделать `cd ..`); README об этом говорит.
- Подтверждение происходит в `agent.py` (не в инструментах) для `write_file`, `edit_file`, `run_bash`; если пользователь отказывает, модель получает `{"ok": False, "error": "user denied this action"}`.

## Порядок работы
1. `uv venv --python 3.12`, установить зависимости, **smoke-тест** крошечного скрипта (не поставляется) с 2–3 моделями-кандидатами: обычный текст + вызов функции + круговой обмен с function-response. Выбрать модель по умолчанию по результату и честно сообщить вам (включая случай нестабильности API).
2. `tools.py` + `tests/test_tools.py`; прогнать тесты.
3. `llm.py`, `agent.py`, `main.py`.
4. Демо-проект; прогнать настоящую сквозную задачу «Fix the failing test.»
5. README, `.env.example`, `.gitignore`.

## Проверка
- `python -m unittest discover tests` проходит.
- `python main.py --workspace ./workspace`, затем «Fix the failing test.» Агент должен исследовать (glob/grep/read), править, запускать тесты и завершать резюме; после этого `cd workspace && python -m unittest` становится зелёным.
- Ручные проверки: путь вроде `../.env` отклоняется; отказ от подтверждения возвращает модели структурированную ошибку; `--max-steps 2` останавливается корректно; в `logs/` появляется JSONL-файл со всеми шагами.
- Итоговый отчёт — на русском; комментарии, docstring'и, README и план — на русском, идентификаторы и тексты для модели — на английском.

## Открытый риск
Эндпоинт Gemini во время моих проверок возвращал несогласованные ответы 404/503. Если он останется нестабильным на момент реализации, я всё равно поставлю код и сообщу точно, какие части проверены вживую, а какие — только модульными тестами.
