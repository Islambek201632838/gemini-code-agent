# Маленький кодинг-агент (клон «Claude Code» для обучения)

Минимальный кодинг-агент примерно на 600 строк Python. Он использует Gemini API
(бесплатный тариф) и написанный вручную цикл агента: без LangChain, LangGraph и ADK.
Смысл в том, чтобы увидеть каждую движущуюся часть.

## Быстрый старт

```bash
uv venv --python 3.12 .venv            # or: python3 -m venv .venv (needs Python 3.10+)
uv pip install --python .venv/bin/python -r requirements.txt
cp .env.example .env                   # then put your key from https://aistudio.google.com/apikey
.venv/bin/python main.py --workspace ./workspace
> Добавь функцию mode() в stats.py и тест к ней.
```

Флаги: `--workspace DIR` (по умолчанию `./workspace`), `--yes` (автоматически одобрять write/edit/bash), `--max-steps N` (по умолчанию 25).
Введите `/exit`, чтобы выйти. Модульные тесты запускаются так: `.venv/bin/python -m unittest discover tests`.

Модель берётся из `GEMINI_MODEL` в `.env`. Доступность моделей на бесплатном тарифе часто меняется:
модель может присутствовать в списке моделей и всё равно возвращать 404 («no longer available to new users»).
Если получаете 404, попробуйте другое имя (`gemini-3.8-flash`, `gemini-flash-latest`, ...).

## Как выглядит вывод

```
● run_bash(python -m unittest)
  ⎿ ✗ завершилось с кодом 1
    FAIL: test_median_even
    AssertionError: 3 != 2.5

? Разрешить edit_file?
  stats.py
  - return ordered[middle]
  + return (ordered[middle - 1] + ordered[middle]) / 2
  Одобрить? [y/N]
```

В консоли только короткие сводки; полные результаты инструментов лежат в `logs/`. Цвета включаются в терминале и отключаются переменной `NO_COLOR=1`.

## Файлы

| Файл | Что делает |
|---|---|
| `main.py` | CLI и REPL. Разбирает флаги, создаёт `LLM` и `Agent`, читает ваши задачи. |
| `agent.py` | Цикл агента, запросы подтверждения, JSONL-лог, защита по максимуму шагов. Вывод в консоль делегирует `ui.py`. |
| `ui.py` | Оформление терминала: баннер, `●` для ответов и вызовов, `⎿` для сводок результатов, diff в подтверждении. Только ANSI, без зависимостей. |
| `llm.py` | Единственный файл, который знает о Gemini. Повторы/backoff, объявления инструментов, конструкторы сообщений. |
| `tools.py` | Шесть инструментов, их схемы/описания, проверка путей, обрезка вывода, denylist. |
| `tests/test_tools.py` | Модульные тесты: выходы за пределы папки, уникальность в `edit_file`, обрезка, denylist. |
| `workspace/` | Демо-проект: маленький модуль `stats.py` с тестами, на нём удобно пробовать агента. |
| `logs/` | Один JSONL-файл на запуск со всеми ответами модели и результатами инструментов (в git-ignore). |
| `CLAUDE.md` | Инструкции проекта для Claude Code и индекс документации. |
| `.claude/docs/` | `architecture.md` (устройство кода), `status.md` (что проверено и что осталось), `plan.md` (исходный план). |

## Как работает цикл

LLM не может трогать ваши файлы. Она умеет только вернуть текст или запрос вроде
«пожалуйста, вызови `read_file` с `path=stats.py`». Реальную работу делает ваша программа:

```
history = [user task]
repeat (at most max_steps times):
    reply = model(history)               # llm.py
    history += reply                     # keep the model's message exactly as returned
    if reply has no tool calls: stop     # plain text = final answer
    for each tool call:
        ask the user if it is write/edit/bash
        result = run the tool            # errors become {"ok": false, "error": ...}
    history += all results as one message
```

На что стоит обратить внимание:
- **Автоматический вызов функций отключён** в `llm.py`; иначе SDK выполнял бы этот цикл за вас.
- **Сообщение модели добавляется без изменений.** Модели Gemini 3 прикрепляют к своим сообщениям
  «thought signatures», и их нужно отправлять обратно как есть. Если пересобрать сообщение из текста, они потеряются.
- **Ошибки инструментов — обычные результаты.** Когда `edit_file` падает, потому что текст не уникален,
  модель читает ошибку и пробует снова. Так агенты восстанавливаются после сбоев.
- **Модель выбирает инструмент по описаниям** в `tools.py`, поэтому в них сказано, когда использовать
  `grep`, а когда `glob`, и `edit_file` вместо `write_file`.
- **Максимум шагов** защищает от бесконечного цикла (и от выжигания квоты).

## Безопасность: что он делает и чего НЕ делает

- Все файловые инструменты разрешают пути и отказывают во всём, что вне рабочей папки (`../`, абсолютные пути, симлинки).
- `write_file`, `edit_file` и `run_bash` сначала спрашивают `y/n` (пропустить можно через `--yes`).
- У `run_bash` есть **denylist** (`sudo`, `rm -rf /`, `mkfs`, конвейер в shell, ...).

**Denylist — это НЕ настоящая безопасность.** Он сопоставляет текстовые шаблоны, а у shell бесконечно много способов сказать
одно и то же (`python -c "import shutil; ..."`, `$(echo cm0= | base64 -d)`, ...). Кроме того, `run_bash` лишь
*запускается* в рабочей папке; команда всё равно может сделать `cd ..` или прочитать любой файл, доступный вашему пользователю. Настоящая защита — подтверждение y/n. Для реальной изоляции используйте
контейнер или виртуальную машину. Не запускайте это с `--yes` на машине или в папке, которые вам дороги.

## Что можно добавить самостоятельно

1. **Режим планирования**: фаза только для чтения (только read_file/glob/grep), где модель предлагает план до любых правок.
2. **Инструкции проекта в стиле CLAUDE.md**: загружать файл из рабочей папки и добавлять его к системному промпту.
3. **Субагенты**: инструмент, который запускает новый `Agent` с собственной историей и возвращает только его резюме.
4. **Хуки**: запускать вашу функцию до/после каждого вызова инструмента и позволять ей блокировать или переписывать вызов.
5. **Сжатие контекста**: когда история становится длинной, просить модель резюмировать старые ходы и заменять их.
6. **MCP-клиент**: находить инструменты на MCP-сервере и предоставлять их рядом со встроенными.
7. **Evals**: набор небольших задач с автоматическими проверками (например, «тесты проходят»), запускаемый многократно для сравнения промптов и моделей.

### Чтобы терминал не зависал

Уже сделано:
- **Таймаут и убийство всей группы процессов.** `run_bash` запускает команду с `start_new_session=True`;
  по таймауту (60 с по умолчанию) и по Ctrl+C делается `os.killpg`, поэтому дочерние процессы не остаются.
- **Команды не ждут ввод.** `stdin=subprocess.DEVNULL`, а описание инструмента просит модель добавлять `--yes` / `-y`.
- **Стриминг вывода.** Вывод читается потоками и показывается по мере появления (до 20 строк на команду),
  а лимит размера (10 000 символов на поток) действует *во время* чтения, так что память не растёт.
- **Ctrl+C посреди задачи.** Прерывает запрос к модели, подтверждение или команду. На каждый `tool_use` в историю
  всё равно добавляется `tool_result` (`{"ok": false, "error": "cancelled by user"}`), поэтому следующий запрос принимается.
- **Защита от зацикливания.** Третий подряд одинаковый вызов (тот же инструмент и аргументы) не выполняется, а модель
  получает подсказку сменить подход; на пятом цикл останавливается.
- **Возобновление сессий.** Каждое сообщение пишется в лог в исходном виде (вместе с thought signatures), поэтому
  `main.py --resume` (самый свежий лог) или `--resume logs/run-….jsonl` восстанавливает `history` и продолжает писать в тот же файл.
- Лимит шагов, ретраи с backoff в `llm.py`, JSONL-лог каждого шага.

Не сделано:
- **Асинхронные сетевые вызовы и подпроцессы (`asyncio`).** Цикл строго последовательный (следующий шаг зависит
  от результата предыдущего), поэтому выигрыш был бы только при параллельных инструментах или подагентах.
- **Псевдотерминал (`pty`)** для по-настоящему интерактивных программ: сейчас они получают EOF на stdin.

### Что отличает «сильный» харнес от простого

Хороший редактор файлов (замена по уникальному фрагменту, проверка перед записью), управление контекстом
(сжатие истории, обрезка вывода), права и подтверждения, режим планирования, субагенты, хуки, MCP, возобновление сессий.
Всё это строится поверх того же цикла. Часть уже есть здесь (`edit_file` по уникальному фрагменту, обрезка, подтверждения,
возобновление сессий); остальное см. в списке выше.
